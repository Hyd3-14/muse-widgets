# muse-widgets

Interactive chat widgets for [Muse](https://muse.ai) — a component catalog, ready-to-use HTML templates, an agent skill that decides when a widget beats plain text, and a validator for the widget contract.

**Demo: [hyd3-14.github.io/muse-widgets](https://hyd3-14.github.io/muse-widgets/)** — all 15 components, live in your browser.

日本語版: [README.ja.md](README.ja.md)

> Unofficial project. Muse is a product of Meta. The widget contract documented here is based on observable behavior, not a published SDK, and may change.

## Why

Muse can render interactive HTML widgets inside a chat: sliders, checklists, calculators, charts. Used well, they beat paragraphs — a quantity the reader can sweep, a checklist whose remaining items the agent can read back, a comparison whose recommendation follows the reader's condition.

But there is no public catalog for them. Agents improvise the markup every time, state handling is rediscovered per conversation, and the same mistakes (browser storage instead of the state bridge, light-only colors, form elements) keep recurring. This repository is the missing catalog, specialized for Muse instead of generic generative UI.

## The catalog in short

Static: card, badge, chip row, timeline, progress bar, comparison grid, button row.

Interactive (state in the bridge, never in browser storage): slider + derived value, segmented control, tabs, interactive chart, editable checklist, input form, calculator, conditional comparison.

Details and state shapes: [catalog/components.md](catalog/components.md).

## Quick start

Build a widget from a template:

1. Pick a component from the catalog.
2. Copy its file from `templates/` and replace the sample content. Keep data embedded in the fragment, separate from the drawing code, and state the unit and period of every number.
3. Check it: `python3 tools/validate-widget.py your-widget.html`

Use the skill: copy `skills/chat-intelligent-ui/` into your agent's skills directory. It teaches the agent the firing rules (fire on a matching signal, stay text for light questions), the component choice table, and the build checklist.

Validate the whole repository: `python3 tools/validate-widget.py` (defaults to `templates/` and `examples/`).

## The contract, briefly

- A widget is an HTML fragment, not a full document, at most 1 MB.
- State lives only in `window.hatchWidget`: seed with `getState(defaults)`, replace in full with `setState(nextState)`, re-render on the `hatch-widget-state` event.
- No `localStorage`, no `<form>`, no hard-coded light-only colors. Style with the `--hatch-widget-*` theme variables so both light and dark themes work.

Full version: [docs/state-bridge.md](docs/state-bridge.md).
