ghq と gwq が補える範囲（workspace 176件・21.5GB に対して）
ghq の射程： clone の置き場の一元化
対象は git 管理下の 28件（4.0GB）と cram 系の clone 群。ghq 管理の root 配下に owner/repo の形で揃うので、「どの repo がどこにあるか」が一意になる。ただし ghq は置き場を決めるだけの道具で、古い clone を消す判断まではしない。
gwq の射程： worktree の作成と削除の管理
一番効くのはここ。cram 系 32件・9.0GB（全体の42%）は、検証や PR ごとに作った独立 clone が捨て忘れられている形。今は全部 git が clean（未コミットの変更なし）なので失うものはない。worktree にすれば .git を共有でき、作ったものの一覧と削除（remove）が道具の側で管理される。pnpm の store 共有と合わせると、clone ごとの二重持ちも減る。
道具で補えない部分： git ですらない作業フォルダ
176件のうち約148件は git 管理下にない（下書き、成果物、ツール実体、データ置き場）。ここは ghq でも gwq でも届かなくて、置き場の規則（作業は work 配下に切る、終わったらアーカイブか削除）の話になる。
まとめると、サイズでは約4割、件数では約2割が道具の射程。残りは運用ルール側。VM には ghq も gwq も未導入（WSL2 側は dotfiles で gwq を運用中）。
