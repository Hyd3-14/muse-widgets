Skills も共有 docs も新 repo を正本にする。既存に引っ張られない度は最大。ただし vault／df と正本が3つに割れ、移行と二重管理のコストが一番大きい。

案B

今の df／vault をその場で prune

作り直しコストは最小。ただし live と正本の食い違い（settings 約8.2倍、agy のルーター参照切れ）みたいな既存の歪みを抱えたまま削るため、削り切れない部分が残る。

推し — 案C

新規は表面だけ、正本は元のまま

home repo は開始点とポインタと最小 Skills だけを持つ薄い殻にする。試験運用はこの形で始め、効いたら正本の移し先を後から決める。作り直しの利点を取りつつ、正本を増やさない。
