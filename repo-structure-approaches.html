agent-lens の現状（実測）

ルートに package main が5ファイル・計3,034行のフラット構成。testdata、docs、CONTRIBUTING は既にある。ビルド済みバイナリは .gitignore 済みで汚染なし。足りないのは cmd／internal 分割、CI、LICENSE、リリース設定。

A. Copier テンプレート ＋ 薄い Skill推奨テンプレ repo に骨格（配置、CI、LICENSE、文書類）を持ち、Skill は質問項目を埋めて copier を回す手順だけ。利点：copier update で後から全 repo へ改善を流せる、repo 名やライセンスで分岐できる。欠点：Copier と jinja の保守が増える、型が固まるまで数 repo 分の試行が要る
B. GitHub の template repository利点：導入コストゼロで「Use this template」ボタンが付く。欠点：生成した後の更新伝播がなく、分岐もできない。一度きりの雛形配布にしかならない
C. gonew（Go 公式の雛形コピー）利点：Go ネイティブで単純。欠点：Go 専用、質問・分岐・更新の仕組みなし。B と同じ限界を持つ
D. Skill にチェックリストだけ持つ利点：いちばん軽く、今すぐ agent-lens の整形にも使える。欠点：毎回手作業で、再現性は文章頼み。repo が増えると効かなくなる

進める順序の提案

いきなりテンプレから作ると空回りする。先に agent-lens の整形を実地でやって型を確定し、その差分を Copier テンプレへ抽出してから Skill 化する。この順なら、テンプレの中身が「実際に使った構造」になる。
