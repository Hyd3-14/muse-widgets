# Component catalog

Seventeen components: eight static, nine interactive. Every entry lists the
template file, what it is for, and — for interactive components — the exact
state shape it keeps in the `window.hatchWidget` bridge.

Rules that apply to all components:

- Outer container always has 16px padding; headings never touch the edge.
- Colors come only from a theme's role variables (`--pal-*`, see
  [themes.md](themes.md)). Every template inlines exactly one theme
  block — the one flagged **In use** in the theme registry — and puts
  its class on the root element. Color is used when it carries meaning,
  and status is always paired with words, never color alone.
- Separation between surfaces is carried by the theme's outer/inner
  color difference. Components have no borders, except hairline
  dividers drawn in the opposite surface's color inside a card.
- Corner radius is 8px. Spacing is a multiple of 4, with 16 and 24 as
  the defaults. The folded card is the exception: square corners,
  because a rounded corner surviving next to a fold reads as a mistake.
- Derived values (totals, percentages) are computed at render time and are
  never stored in state.

## Static components

| Component | Template | Use it for |
| --- | --- | --- |
| Card | `templates/card.html` | One self-contained point: a summary, a result, a notice |
| Badge | `templates/badge.html` | A single status word that matters (Recommended, Done, Blocked) |
| Chip row | `templates/chip-row.html` | Attributes at a glance; not for choices |
| Timeline | `templates/timeline.html` | Ordered steps or events with times |
| Progress bar | `templates/progress-bar.html` | Segmented progress, always with counts in words |
| Comparison grid | `templates/comparison-grid.html` | Two to four options side by side with one hero value each |
| Folded card | `templates/folded-card.html` | Nested mini-cards separated by palette color difference instead of borders; the bottom-right corner is cut away and the fold falls inside. Square corners, no border |
| Button row | `templates/button-row.html` | Shared button styling and states |

### Folded card palettes

The folded card uses the same theme system as every other component;
its palettes are the catalog's themes. See [themes.md](themes.md) for
the registry, the role variables, and how to add a variation.

## Interactive components

State is replaced in full on every change (`setState(nextState)`), seeded
with `getState(defaults)`, and re-rendered on the `hatch-widget-state`
event. See [docs/state-bridge.md](../docs/state-bridge.md).

| Component | Template | State shape | Use it for |
| --- | --- | --- | --- |
| Slider + derived value | `templates/slider-linked-value.html` | `{ value: number }` | One quantity the reader wants to sweep while a total follows |
| Segmented control | `templates/segmented-control.html` | `{ selected: string }` | Two to five discrete options with a short explanation each |
| Tabs | `templates/tabs.html` | `{ tab: string }` | Up to four sections whose content all ships in the fragment |
| Interactive chart | `templates/interactive-chart.html` | `{ metric: string }` | Switching the metric of one chart; data embedded, units and period stated |
| Editable checklist | `templates/editable-checklist.html` | `{ checked: string[] }` | Tasks the reader ticks off; the agent reads back what remains |
| Input form | `templates/input-form.html` | `{ fields: {...}, submitted: boolean }` | Up to five short fields; never secrets, payment details, or IDs |
| Calculator | `templates/calculator.html` | `{ <input>: number, ... }` | Several inputs, premises stated up front, one hero result, rounding rule stated |
| Conditional comparison | `templates/conditional-comparison.html` | `{ condition: string }` | A table whose numbers stay fixed while the recommendation moves with the reader's condition |
| Before/After slider | `templates/before-after-slider.html` | `{ pos: number }` | Two forms of the same material stacked; dragging reveals the figure form over the prose form (or any two states of the same content) |

## Adding a component

Add a component only when a real conversation needed one and the existing
sixteen could not express it. A new entry needs: a template that passes
`tools/validate-widget.py`, a row in this catalog with its state shape, and
a demo section generated by `tools/build-demo.py`.
